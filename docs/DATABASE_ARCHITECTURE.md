# 豆苗プランター データベース構成図

## 📊 データベース概要

豆苗プランターシステムは、責任分離とパフォーマンス最適化のため、2つの独立したSQLiteデータベースを使用しています。

## 🗃️ データベース一覧

### 1. main.db - メインデータベース
**用途**: アプリケーションの主要データ保存
**ファイルパス**: `data/main.db`
**管理モジュール**: `src/data/data_manager.py`

#### テーブル構成
- `sensor_data` - センサーデータ（温度、湿度、水圧）
- `watering_history` - 給水履歴
- `camera_history` - カメラ撮影履歴
- `ai_consultation_history` - AI相談履歴
- `notification_history` - 通知履歴
- `settings` - システム設定

### 2. scheduler.db - スケジューラーデータベース
**用途**: APSchedulerのジョブ管理
**ファイルパス**: `data/scheduler.db`
**管理モジュール**: `src/utils/scheduler.py`

#### テーブル構成
- `apscheduler_jobs` - スケジュールジョブ（APScheduler管理）

## 🏗️ アーキテクチャ設計

### 責任分離の原則
1. **main.db**: ビジネスロジックのデータ
2. **scheduler.db**: システム管理のデータ

### パフォーマンス最適化
- **独立したアクセス**: スケジューラーとアプリケーションが独立してアクセス
- **ロック競合回避**: 異なるデータベースでロック競合を回避
- **並行処理**: 複数のモジュールが同時にデータベースにアクセス可能

### 保守性の向上
- **バックアップ分離**: スケジューラーデータとアプリケーションデータを分離
- **障害分離**: 一方のデータベースに問題があっても他方に影響しない
- **メンテナンス**: 個別にデータベースのメンテナンスが可能

## 🔧 技術仕様

### SQLite設定
- **文字エンコーディング**: UTF-8
- **接続プール**: なし（単一接続）
- **トランザクション**: 自動コミット
- **バックアップ**: 手動（将来自動化予定）

### データ保持期間
- **センサーデータ**: 90日間
- **画像データ**: 30日間
- **ログデータ**: 30日間
- **設定データ**: 永続保持
- **スケジュールジョブ**: 永続保持

## 📈 パフォーマンス指標

### データベースサイズ目安
- **main.db**: 約50MB（90日分のセンサーデータ）
- **scheduler.db**: 約1MB（スケジュールジョブ）

### アクセス頻度
- **main.db**: 高頻度（センサーデータ書き込み）
- **scheduler.db**: 低頻度（スケジュール変更時のみ）

## 🛠️ メンテナンス

### 定期メンテナンス
```bash
# データベース最適化
sqlite3 data/main.db "VACUUM;"
sqlite3 data/scheduler.db "VACUUM;"

# データベース整合性チェック
sqlite3 data/main.db "PRAGMA integrity_check;"
sqlite3 data/scheduler.db "PRAGMA integrity_check;"
```

### バックアップ
```bash
# メインデータベースのバックアップ
cp data/main.db data/backup/main_$(date +%Y%m%d).db

# スケジューラーデータベースのバックアップ
cp data/scheduler.db data/backup/scheduler_$(date +%Y%m%d).db
```

## 🔍 トラブルシューティング

### よくある問題
1. **データベースロック**: 複数のプロセスが同時にアクセス
2. **ディスク容量不足**: ログローテーションの設定確認
3. **権限エラー**: ファイルの読み書き権限確認

### 解決方法
1. **プロセス確認**: `ps aux | grep python`
2. **ディスク容量**: `df -h`
3. **権限確認**: `ls -la data/*.db`
